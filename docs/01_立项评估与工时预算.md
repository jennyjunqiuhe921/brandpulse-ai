## 一、执行摘要（一页结论）

| 项 | 结论 |
|---|---|
| 产品性质 | 生产级三端 B2B SaaS（多租户 / 登录 / RBAC / 审计 / 数据库），**非 demo 量级** |
| 完整版工期 | 5–7 人团队约 **6–10 个月**（人力约 80–115 人·周） |
| MVP 工期 | **3–4 个月**（可交付真实客户试用） |
| 人力成本 | 约 **80 万–140 万 RMB**（5–6 人 × 7 个月，随团队水平/城市浮动） |
| 关键外部成本 | 第三方合规数据源订阅（年费 **几万–几十万**）、LLM API、云基础设施 |
| 复用率 | 现有 Streamlit 版的 **AI/业务逻辑（prompt、分析、合规模块）可直接复用**；外壳需重写 |
| 核心建议 | **分三阶段**：现有 demo 拿单拿奖 → MVP 验证付费 → 完整版扩张，现金流友好、风险可控 |

---

## 二、为什么是这个量级

现有 Streamlit 版本 ≈ PRD 的「执行层一个端」，且为**单用户 / 文件存储 / 无登录**。
新 PRD 要求的多租户、登录、RBAC、审计、数据库，意味着**应用外壳要重写**；最吃工时的是**底层基础设施**（认证、隔离、网关、工作流、审计），而非业务功能本身。业务逻辑（提示词、分析、合规）可平移复用。

## 三、工作分解结构（WBS）与工时

## 六、关键风险与假设

**风险**
1. **数据采集合法性**（最大风险）：主流 UGC 平台禁止直接抓取，决定了「真采集 vs 模拟」的成本与合规路径。
2. **范围蔓延**：PRD 功能多，若不分阶段，极易拖期。
3. **多租户与审计**：隔离与不可篡改日志是商用底线，返工代价高，需一次设计到位。
4. **AI 质量与合规**：调性匹配率/合规检出率等指标需持续调优。

**假设**
- 团队为熟练工程师；需求在阶段内基本冻结。
- LLM 走外部 API（不自建大模型）。
- 第三方数据源以采购/集成方式接入，不自研爬虫规避法律风险。

## 七、结论与建议路径

**分三阶段，每阶段都有可交付物，风险可控、现金流友好：**

| 阶段 | 内容 | 周期 |
|---|---|---|
| **现在** | 保留 Streamlit demo，用于赛事/销售演示 | ✅ 已完成 |
| **MVP** | 真后端：登录+RBAC+单租户+执行层全量+管理层 1 个驾驶舱，可给真实客户试用 | 3–4 个月 |
| **完整版** | 补齐多租户运营后台、多级审批、审计台账、ROI、行业模板等全 PRD | 再 3–6 个月 |

先用 demo 拿单/拿奖 → MVP 验证付费意愿 → 再决定是否投完整版。
