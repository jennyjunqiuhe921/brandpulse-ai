# 智营 AI · MVP 功能边界与技术架构

> 配套文档：PRD V1.1 + 立项评估
> 目标周期：3–4 个月　|　目标：可交付真实客户试用的最小可行产品
> 用途：开发排期起点 / 技术评审 / 验收基线

---

## 一、MVP 目标与原则

**一句话目标**：做出一个**单租户即可跑通「登录 → 角色 → 执行全链路 → 管理层看板」**的真后端产品，验证付费意愿。

**取舍原则**
1. 先做**地基**（登录/RBAC/数据库/AI 网关），它是其它一切的前提。
2. **执行层全量保留**（这是真实场景刚需，且现有逻辑可复用）。
3. 管理层**只做 1 个驾驶舱 + 基础审批**，证明「管控价值」即可。
4. 运营侧**暂缓**多租户后台，MVP 阶段用「单租户 + 配置文件」替代。
5. 数据采集 MVP 用**模拟 + 1 个合规数据源样例**，规避法律风险。

## 二、范围边界（In / Out）

### ✅ MVP 纳入
| 层 | 功能 |
|---|---|
| **全局地基** | 邮箱/账号登录、JWT 鉴权、RBAC 三角色、前后端权限拦截、标准布局(顶部+左菜单+状态栏)、AI 网关(路由/调用量统计/日志)、审计日志(基础)、消息中心(基础)、四区块/溯源/免责全局组件 |
| **执行层（全量）** | 工作台、数据采集(关键词分组/渠道/历史复用)、文案生成(双模式/多版本/合规预检/热度评分)、GEO(关键词组/竞品/地域/E-E-A-T)、舆情(五级风险/话术库/历史)、合规自查、资产库、我的审批 |
| **管理层（精简）** | 1 个管理驾驶舱(内容/舆情/GEO/合规 4 项核心指标 + 数据下钻)、企业级任务列表(只读全员)、单级审批中心 |
| **任务通用能力** | 优先级/标签/截止时间、列表+看板视图、超时提醒 |

### ❌ MVP 暂不做（留给完整版）
- 多租户运营后台（租户管理/套餐/计费）→ MVP 单租户
- 大模型/Prompt 管理中心 UI → MVP 用配置文件
- 多级/多条件分支审批、在线评论协作 → MVP 单级审批
- ROI 看板、自定义报表、定时推送
- 舆情传播可视化、负面案例库、细分标签
- 文案侧边素材栏、分支版本树、多平台预览
- 行业模板市场、冷启动向导
- 生图/生视频大模型
- 组织架构(部门/门店/子品牌)分级

## 三、MVP 功能清单（按角色）

**平台默认（单租户，超管在配置层）**
- 大模型、Prompt、行业词库以**配置文件/初始化脚本**注入（暂无 UI）

**企业领导（管理层）**
1. 管理驾驶舱（4 核心看板 + 点击下钻到明细）
2. 企业级任务列表（全员只读）
3. 审批中心（单级：待我审批/我已审批/我发起）
4. 账号管理（新增/冻结员工）
5. 合规&审计查询（基础）

**市场人员（执行层）**
1. 个人工作台（待办聚合 + 优先级/标签/截止 + 看板视图）
2. 数据采集（关键词分组/渠道/地域/历史复用）
3. 文案生成（快速/高级双模式、多版本、合规预检、热度评分）
4. GEO（关键词组、竞品对标、地域、E-E-A-T 输出）
5. 舆情分析（五级风险、话术库、历史）
6. 合规自查（批量检测）
7. 资产库（复用）
8. 我的审批（发起/兼审）
9. 个人中心

## 四、技术架构

### 4.1 技术栈
| 层 | 选型 | 理由 |
|---|---|---|
| 前端 | React + TypeScript + Ant Design Pro | 企业中后台标配，组件齐全，三角色菜单/权限好做 |
| 后端 | **Python + FastAPI** | ★ 直接复用现有 prompt/分析/合规模块，AI 生态最顺 |
| 数据库 | PostgreSQL | 关系型 + 多租户(行级安全/schema)；可用 pgvector 替代向量库 |
| 缓存/队列 | Redis + Celery | 采集/分析异步任务、限流、会话 |
| 向量库 | 保留 Chroma 或 pgvector | RAG 知识库 |
| 对象存储 | S3 / 阿里云 OSS | 文件、导出、水印 |
| 鉴权 | JWT + RBAC | 无状态、前后端双拦截 |
| 部署 | Docker（MVP 单机 docker-compose；后期 K8s） | 简单可控 |

### 4.3 多租户与权限（MVP 简化）
- **MVP**：单租户（`tenant_id` 字段全表预留，但只跑一个租户），为完整版多租户铺好底。
- **RBAC**：`role ∈ {platform_admin, enterprise_admin, market_staff}`；权限矩阵存表，API 入参带 `role`，前端控菜单显隐 + 后端二次拦截。
- **数据权限**：执行层只见个人数据，管理层见全员，按 `owner_id` / `role` 过滤。

### 4.4 核心数据模型（MVP 最小集）
```
tenants(id, name, industry, plan, ...)
users(id, tenant_id, role, name, status, ...)
brands(id, tenant_id, name, tone, brand_words, forbidden_words, ...)
kb_documents(id, brand_id, source, size, added_at, ...)   # 向量在 pgvector
content_tasks(id, tenant_id, owner_id, brand_id, status, priority,
              tags, due_at, meta, output, ...)
geo_tasks / sentiment_tasks / collect_tasks(...)          # 各模块任务
approvals(id, task_ref, applicant_id, approver_id, status, comment, ...)
audit_logs(id, tenant_id, user_id, action, target, ts, immutable)  # 只增不改
messages(id, user_id, type, content, read, ts)
ai_call_logs(id, tenant_id, user_id, module, model, tokens, ts)   # AI 网关计量
```

### 4.5 现有代码复用映射（不白做）
| 现有 Streamlit 资产 | MVP 去向 |
|---|---|
| `prompts/*`（GEO/文案/舆情/合规提示词） | 直接搬进 FastAPI 业务服务 |
| `modules/*`（分析/合规/风险/采集逻辑） | 包装成后端 service |
| `config/*_tasks.py`（任务存储） | 换成 PostgreSQL 表 + ORM |
| `core/rag_engine.py`（RAG） | 换 Chroma→pgvector，逻辑保留 |
| `core/llm_client.py` | 升级为「统一 AI 网关」(加计量/限流/日志) |
| 五级风险/话术库/合规词库 | 直接复用 |
| Streamlit 页面 | 重写为 React 页面（业务规则照搬） |

## 六、MVP 验收基线（Done 标准）

1. 三角色可登录，菜单/数据按权限正确隔离；
2. 执行层全链路：采集→文案/GEO/舆情→合规→（送审）→归档，可走通；
3. 所有 AI 输出含**四区块分类 + 溯源 + 免责**，正式内容**强制人工复核**才能导出；
4. 管理驾驶舱 4 看板有真实聚合数据，指标可下钻到明细；
5. 审批：执行层发起 → 管理层审批 → 留痕不可改；
6. 审计日志只增不改、可导出；AI 调用有计量日志；
7. 移动端核心查看/审批可用；
8. 单租户可独立部署交付给 1 个试用客户。
